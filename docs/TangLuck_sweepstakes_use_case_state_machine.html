Tang Luck Sweepstakes 合规状态机图 + Use Case 表格清单

来源：基于 TangLuck_sweepstakes_use_case_catalog.html 的 use case 清单重组。现在按业务分类组织：同一分类下同时放状态机图和原版表格清单，方便产品、后端、风控、合规、QA 在同一上下文里做实现与验收。

版本：v1.1
日期：2026-06-17
适用前提：无美国博彩牌照，只走 sweepstakes / social casino 路线。默认规则是 fail closed：位置、身份、税务、风控、账本、配置任何一项不确定，都不能开放 SC、SC Game、Redeem。

0. 阅读规则

正常状态用户或订单可继续向下一步流转。
守卫状态必须通过规则校验；不通过就转入阻断、审核或冻结。
阻断状态禁止高风险功能，通常只允许 GC-only 或完全拒绝。
审核状态需要人工、法务、风控、运营或财务处理。
P0核心状态MVP 上线前必须实现并可回归测试。
  • 每个箭头代表一次状态转移；箭头上方是触发事件或守卫条件。
  • 状态机只表达产品和系统必须执行的合规动作，不替代逐州 legal memo。
  • 所有转移都必须记录：用户、时间、规则版本、输入证据、决策结果、操作者。

9. MVP P0 与验收口径

MVP 状态机验收口径

必须 fail closed 的状态
  • 位置未知、GPS/IP 冲突、VPN/代理命中。
  • 州规则缺失、供应商服务失败、后台配置异常。
  • KYC、税务、账户归属、账本任一项未通过。
必须人工审核的状态
  • 高额兑换、首次兑换、账户归属冲突。
  • 退款、拒付、套利、多账号、设备异常。
  • KYC 失败补件、POA 冲突、税务资料异常。
必须版本化留痕的状态
  • Official Rules、AMOE、No Purchase Necessary。
  • state_policy、feature flag、商品包、促销规则。
  • 每一次放行、阻断、冻结、解冻、审核、出款。
验收问题 必须状态机结果
禁止州用户能不能领取 SC、进入 SC Game、兑换？ 必须转入 No-go Blocked，禁止 SC/Game/Redeem/Push。
用户拒绝定位或定位服务失败能不能继续兑换？ 必须转入 Fail Closed，不得开放高风险功能。
用户未 KYC 或 KYC 失败能不能提现？ 必须停在 KYC Pending / KYC Rejected，不得进入 Redeem Submitted。
用户能不能直接购买 SC？ 支付状态机必须阻断 SC SKU，发现即进入 发布阻断。
兑换申请能不能不冻结余额就创建？ 不能；必须先进入 Balance Frozen，冻结失败不得创建申请。
出款能不能自动秒提？ 不能；必须进入 审核中，通过税务、账户、风控和人工审核后才出款。
某州法规变化后旧会话能不能继续玩？ 不能；state_policy 发布或 Kill Switch 后必须重新计算并阻断旧会话。
客服能不能手动绕过州限制补发 SC？ 不能；客服补偿也必须经过 Geo、用户状态、风控和审批状态机。
