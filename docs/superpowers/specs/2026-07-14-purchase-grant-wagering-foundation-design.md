# 购买/入金与流水底座设计

日期：2026-07-14

## 1. 背景

当前项目处于底座建设阶段，没有历史包袱，应优先建立能长期扩展的购买、充值、赠送、活动、钱包和流水模型。

现有实现已经具备部分钱包能力：

- 币种配置：`gl_wallet_currency`
- 钱包账户：`gl_wallet_account`
- 账变流水：`gl_wallet_transaction`
- 资金属性模板：`gl_wallet_fund_property_template`
- 流水任务快照：`gl_wallet_turnover_task`
- 币种策略：`gl_wallet_currency_policy`
- 促销奖励：`gl_promotion_reward`

但当前促销奖励页和资金属性的关系仍然容易误导设计：运营不应该选择资金属性，也不应该用一个通用奖励表承载正常购买、首充、充值活动、折扣、召回、真金入金等全部业务。

本设计以“购买/入金事件 -> 资金发放项 -> 钱包入账 -> 流水义务”为核心模型，重新定义底座边界。

## 2. 设计原则

1. 运营配置业务规则，不配置账务技术分类。
2. 钱包只负责账户、账变、冻结、流水任务、提款/兑换限制判断。
3. 购买/入金业务负责用户支付、购买产品、优惠匹配、发放项生成。
4. 活动业务负责谁能参加、何时参加、奖励如何计算。
5. 每次入账必须生成不可变快照，后续配置变更不影响历史订单和历史流水任务。
6. 多币种能力、地区限制、人群限制必须从第一天纳入模型。
7. 当前 Sweepstakes 模式和后期真金模式必须共用同一套底座。

## 3. 关键业务判断

### 3.1 当前模式

当前更接近 Sweepstakes 模式：

- 用户购买 GC。
- 平台可能赠送 SC。
- GC 当前不可提款、不可兑换，因此不需要流水。
- SC 可用于兑换/兑付，因此赠送彩金通常需要流水。

### 3.2 后期真金模式

后期启用真金模式后：

- 真金本金可提款。
- 为反洗钱，真金本金必须满足游戏流水后才可提款。
- 赠送金额可以要求更高流水。
- 本金和赠送可以分别打码，也可以合并同倍打码。

因此底座不能写死“充值本金不打码”或“只有活动赠送打码”。

## 4. 领域模型

### 4.1 Currency Capability 币种能力

定义币种在不同地区、用户分组、渠道下能做什么。

| 字段 | 说明 |
| --- | --- |
| `currencyCode` | 币种，如 GC、SC、USD |
| `playEnabled` | 是否可游戏 |
| `withdrawEnabled` | 是否可提款 |
| `redeemEnabled` | 是否可兑付/兑换礼品 |
| `exchangeInEnabled` | 是否允许兑换入 |
| `exchangeOutEnabled` | 是否允许兑换出 |
| `visibleToClient` | C 端是否展示 |
| `defaultWageringRequired` | 入账后是否默认需要流水 |
| `defaultWageringMultiplier` | 默认流水倍数 |
| `regionScope` | 地区范围 |
| `userSegmentScope` | 用户分组范围 |

产品规则：

- GC 当前 `withdrawEnabled = false`，`redeemEnabled = false`，默认不需要流水。
- SC 当前可兑付/兑换时，赠送入账通常需要流水。
- USD 等真金币种后期 `withdrawEnabled = true`，默认需要 AML 流水。

### 4.2 Purchase Offer 购买产品/优惠

购买产品统一承载正常购买、首购、充值活动、折扣、召回、包体优惠。

| 类型 | 示例 | 说明 |
| --- | --- | --- |
| 普通购买 | 支付 10 USD 获得 10000 GC | 常规商店套餐 |
| 首购优惠 | 首次支付 20 USD，额外送 5 SC | 首充/首购 |
| 充值活动 | 充值满 100 送 20 SC | 周期性充值赠送 |
| 折扣产品 | 原价 20，折扣价 10 | 购买价格优惠 |
| 召回优惠 | 召回用户专属包 | 限指定人群 |

运营配置项：

| 配置项 | 说明 |
| --- | --- |
| 产品/活动名称 | C 端展示和 B 端识别 |
| 支付币种与支付金额 | 用户实际支付 |
| 发放项 | 支付成功后给哪些币种、多少数量 |
| 适用用户 | 全部、新用户、召回用户、指定标签 |
| 适用地区 | 全部或指定国家/地区 |
| 生效时间 | 开始/结束时间 |
| 购买限制 | 首次、每日一次、总限一次、周期限购 |
| 叠加规则 | 是否可叠加其他优惠 |
| 状态 | 草稿、启用、停用 |

### 4.3 Grant Item 资金发放项

一次购买或活动可以生成多笔发放项。

| 发放项 | 业务含义 | 系统资金属性 |
| --- | --- | --- |
| 购买获得 GC | 用户购买得到的游戏币 | `PURCHASE_GRANT_GC` |
| 购买赠送 SC | 购买附赠的 SC | `PURCHASE_BONUS_SC` |
| 真金本金 | 用户真实入金 | `DEPOSIT_PRINCIPAL` |
| 充值赠送 | 入金活动赠送 | `DEPOSIT_BONUS` |
| 活动奖励 | 普通活动发奖 | `ACTIVITY_REWARD` |
| 每日奖励 | 每日登录发奖 | `DAILY_REWARD` |
| 邀请奖励 | 邀请活动发奖 | `INVITE_REWARD` |
| 任务奖励 | 任务完成发奖 | `TASK_REWARD` |

运营不选择资金属性。系统根据业务类型和发放项类型自动映射。

### 4.4 Wagering Obligation 流水义务

流水义务是钱包入账后的约束快照，不是活动配置本身。

| 字段 | 说明 |
| --- | --- |
| `memberId` | 会员 |
| `currencyCode` | 需要完成流水的币种 |
| `creditAmount` | 入账金额 |
| `requiredTurnover` | 所需流水 |
| `completedTurnover` | 已完成流水 |
| `wageringMode` | 不需要、固定金额、倍数、合并同倍 |
| `gameScopeType` | 全部、分类、厂商、指定游戏 |
| `gameScopeValue` | 范围值 |
| `expireTime` | 流水有效期 |
| `sourceOrderNo` | 来源订单 |
| `sourceActivityNo` | 来源活动 |
| `ruleSnapshot` | 规则快照 |

核心规则：

- 流水义务在用户支付成功、活动领取、任务完成等业务触发时生成。
- 历史流水任务不跟随活动配置变化。
- 提款/兑换判断读取未完成流水义务。

## 5. 充值/购买流水模式

购买或入金类业务必须支持以下模式。

| 模式 | 说明 | 示例 |
| --- | --- | --- |
| 不需要流水 | 用于不可提不可兑币种 | GC 当前模式 |
| 本金流水 | 入金本金需 AML 流水 | USD 100 需 1 倍流水 |
| 赠送流水 | 只对赠送金额打码 | 赠送 SC 5 需 10 倍流水 |
| 本金+赠送同倍 | 按本金和赠送合计打码 | 充值 100 送 20，按 120 * 3 |
| 分别计算 | 本金和赠送不同倍数 | 本金 1 倍，赠送 10 倍 |
| 固定金额 | 直接指定流水金额 | 固定完成 200 流水 |

默认建议：

- 当前 GC 发放：不需要流水。
- 当前 SC 赠送：需要流水，默认赠送金额 * 10。
- 后期真金本金：需要流水，默认本金 * 1。
- 充值活动赠送：需要流水，默认赠送金额 * 10，可由活动覆盖。

## 6. B 端菜单建议

### 6.1 支付/购买中心

```text
支付/购买中心
  购买产品
  购买优惠
  支付订单
  入金记录
```

购买产品用于配置常规套餐，例如购买 GC 赠送 SC。

购买优惠用于配置首购、充值活动、折扣、召回等规则。

### 6.2 促销中心

```text
促销中心
  每日登录
  邀请活动
  任务活动
  普通派奖
  活动参与记录
  活动发奖记录
```

促销中心不承载支付成功后的购买产品逻辑。

### 6.3 钱包中心

```text
钱包中心
  币种配置
  币种能力策略
  钱包账户
  账变流水
  流水任务
  资金属性
  币种兑换规则
  人工调账
```

资金属性属于高级系统配置，不是普通运营日常配置项。

## 7. C 端展示原则

C 端购买页展示业务语言：

- 支付金额
- 获得 GC
- 赠送 SC
- 限购规则
- 活动时间
- 流水/兑换限制说明

示例：

```text
支付 $10
获得 10,000 GC
赠送 1 SC
SC 需完成 10 倍游戏流水后可兑换
GC 不可提款或兑换
```

真金模式示例：

```text
充值 $100
到账 $100
需完成 1 倍游戏流水后可提款
```

## 10. 模块边界

### 10.1 购买/支付域

负责：

- 购买产品配置
- 优惠匹配
- 支付订单
- 支付成功后生成发放项
- 调用钱包入账

不负责：

- 钱包余额计算
- 流水核销
- 提款审批

### 10.2 促销域

负责：

- 每日登录
- 邀请
- 任务
- 普通派奖
- 活动资格判断
- 活动发奖记录

不负责：

- 支付订单
- 购买套餐
- 真金 AML 流水默认规则

### 10.3 钱包域

负责：

- 账户余额
- 账变流水
- 冻结/释放
- 流水任务
- 提款/兑换限制判断
- 币种能力策略

不负责：

- 购买产品规则
- 活动资格规则
- 优惠叠加规则

## 11. 当前实现处理建议

### 11.1 暂停继续扩展促销奖励弹窗

当前 `促销奖励` 页面不应继续承担充值、购买、首充、召回、折扣逻辑。

短期只保留：

- 每日登录
- 普通派奖

并移除运营界面上的资金属性展示。

### 11.2 新建购买产品模块

下一阶段优先建设：

- B 端购买产品列表
- B 端购买产品表单
- 发放项配置
- 流水策略配置
- C 端购买产品接口
- 支付成功后发放快照和流水快照

### 11.3 钱包侧保持底层能力

保留并强化：

- 币种能力策略
- 资金属性模板
- 流水任务快照
- 账变流水

但资金属性不再暴露给普通运营业务表单。

## 12. 验收标准

1. 运营配置购买产品时，不需要理解资金属性。
2. 运营可以配置购买 GC 赠送 SC，并分别控制 GC/SC 是否需要流水。
3. 当前 GC 不可提不可兑时，系统默认不生成 GC 流水任务。
4. 当前 SC 赠送可配置流水倍数，并生成不可变流水快照。
5. 后期新增 USD 真金币种时，可配置本金默认 1 倍 AML 流水，不需要重构活动模块。
6. 首购、充值活动、折扣、召回都能复用购买产品/优惠模型。
7. 每次支付成功后生成订单发放快照，后续配置修改不影响历史订单。
8. 钱包流水任务可按来源订单、来源活动、币种、状态查询。
9. C 端展示业务语言，不展示 `fundPropertyCode`、`sourceType` 等技术字段。
10. B 端资金属性只作为高级系统配置，不作为普通活动配置入口。

## 13. 推荐实施阶段

### 阶段一：止损和边界收敛

- 促销奖励页只保留每日登录和普通派奖。
- 移除普通运营表单中的资金属性展示。
- 文案改为业务语言。
- 明确充值/购买不从促销奖励页配置。

### 阶段二：购买产品底座

- 新增购买产品/优惠表。
- 新增发放项模型。
- 新增订单发放快照。
- 支付成功后按发放项调用钱包入账。
- 生成流水任务快照。

### 阶段三：C 端购买体验

- 展示购买套餐。
- 展示 GC/SC 获得和赠送。
- 展示流水/兑换限制说明。
- 支持地区和用户分组过滤。

### 阶段四：真金模式预留

- 增加真金币种配置。
- 启用本金 AML 流水。
- 提款判断接入未完成流水任务。

## 14. 不做事项

本阶段不做：

- 完整支付通道接入。
- 复杂 VIP 分层优惠。
- 多活动叠加优先级引擎。
- 自动风控评分。
- 真实提款链路。

这些能力可以在购买/发放/流水底座稳定后扩展。
