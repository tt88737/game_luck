# 购买产品弹窗布局优化设计

## 目标

优化 B 端“购买产品”新增与编辑弹窗的录入体验，解决字段控件过窄、文本截断、发放项横向拥挤、内容区与底部操作区关系不稳定的问题。

本次仅调整 `admin-ui/src/views/payment/purchase-offer/index.vue` 的结构和样式，不修改字段、默认值、校验规则、提交逻辑、接口或后端行为。

## 页面任务与信息层级

运营人员需要依次完成三组配置：

1. 基础信息：产品名称、产品类型、状态等。
2. 支付设置：支付币种、支付金额、限购方式及其条件字段。
3. 发放项：配置一个或多个资金发放项及对应流水和游戏范围。

弹窗采用“标题、可滚动表单、固定底部操作区”三段式结构。基础信息和支付设置作为普通分区；每个发放项作为独立重复单元展示，不嵌套额外装饰卡片。

## 布局设计

- 弹窗目标宽度约 `1200px`，同时受视口宽度约束。
- 表单主体设置独立最大高度和纵向滚动，弹窗标题与底部按钮保持可见。
- 基础信息和支付设置在桌面端采用三列网格。
- 发放项使用三列网格，标签位于控件上方，输入框、数字框和下拉框占满所在网格。
- 流水模式、游戏范围等条件字段按数据状态自然加入网格并换行，不强制保持单行。
- 发放项标题展示序号；删除操作使用带提示的图标按钮；只有一个发放项时沿用现有禁删规则。
- “新增发放项”位于发放项列表末尾，与重复单元保持明确层级。
- 底部“取消”和“确定”按钮保持现有操作语义，提交中状态沿用现有实现。

## 响应式规则

- 宽桌面：三列网格。
- 视口宽度不大于 `1200px`：发放项和普通分区降为两列。
- 视口宽度不大于 `768px`：降为单列，弹窗接近全宽，字段不得横向溢出。
- 所有控件使用稳定的 `width: 100%` 和合理的最小宽度，动态字段出现时不得挤压相邻字段。

## 状态与错误处理

本次不增加新的业务状态。继续使用现有 Element Plus 表单校验、必填提示、提交 loading、接口成功和接口失败反馈。布局必须支持：

- 新增时的默认两条发放项。
- 编辑时不同数量的发放项。
- 无流水、固定流水、倍数流水对应的条件字段。
- 全部游戏和指定范围对应的条件字段。
- 表单校验错误信息出现后不遮挡相邻控件。

## 验证与验收

- 运行购买产品页面相关单元检查或前端构建。
- 使用浏览器实际打开新增弹窗。
- 截图检查 `1440x900` 与 `1366x768` 桌面视口。
- 使用窄视口检查两列和单列降级行为。
- 检查长标签、下拉值、数字精度和校验提示不存在截断、重叠或横向溢出。
- 验证新增、删除发放项及切换流水模式后布局稳定。
- 验证取消和确定按钮在表单滚动时仍可访问。

## 非目标

- 不修改购买产品的数据模型和 API。
- 不增加或删除业务字段。
- 不重构购买产品列表页。
- 不改变后端、字典或国际化文案。
